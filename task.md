# DialScope implementation status

## Scope

Offline Node.js and strict TypeScript phone-data cleaning toolkit for phone-number validation, metadata-backed number type, national/international/E.164 formatting, numbering area, original-carrier, and possible time-zone metadata. Supports bounded CSV input, opt-in contact cleaning and deduplication, batch summaries, side-effect-free Node.js package exports, and an explicitly started optional Fastify API. No live lookup service, caller-name integration, database, tracking, or automatic number persistence.

The following approved toolkit expansion phases supersede the earlier draft scope where they overlap. They retain the existing CLI and library contracts unless a new opt-in mode is selected. Caller-name lookup and linked-account discovery remain roadmap features; Phase 16 research found no integration that meets the documented coverage, access, contract, and evidence requirements.

## Dependency and metadata findings

`libphonenumber-geo-carrier` 2.0.0 documents and types async `geocoder(PhoneNumber, locale?)`, `carrier(PhoneNumber, locale?)`, and `timezones(PhoneNumber)` exports. Its package metadata declares MIT and Node-only operation. It bundles mapping data and documents English fallback when a locale is unavailable. `libphonenumber-js/max` 1.12.31 provides full validation metadata and formatting and declares MIT. Google's upstream libphonenumber source is Apache-2.0 licensed. Exact package versions are pinned in `package.json` and `package-lock.json`; dependencies do not separately expose upstream metadata build versions. Bundled metadata is a snapshot and may lag updates. Third-party license copies/notices are included.

The real metadata adapter returned Zurich and Europe/Zurich for `+41431234567`, and carrier metadata for the documented China Telecom mobile example `+8619912345678`.
